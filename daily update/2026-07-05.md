# Daily Update — 2026-07-05

## Firestore security rules refactor

### Problem
Completing a daily puzzle failed with `cloud_firestore/permission-denied` when updating streak stats on `userGameStates/{uid}`. The old rules validated the **entire merged document** on every partial update, so writes failed when unrelated fields were missing or when only a subset of fields changed.

### Solution
Replaced the monolithic `userGameStates` update rule with **operation-scoped rules** that match how the app actually writes data:

| Operation | Allowed changed fields |
|---|---|
| Daily streak | `streak`, `lastStreakDate`, `longestStreak`, `completedGames`, `totalGames`, `updatedDate` |
| Story mode stats | `detectivePoints`, `storyModeStreak`, `lastStoryModeStreakDate`, `storyModeLongestStreak`, `updatedDate` |
| Hint balance | `hintPackBalance`, `updatedDate` |
| Remove ads IAP | `hasRemoveAds`, `updatedDate` |
| Detective Pro IAP | `isDetectivePro`, `hasRemoveAds`, `updatedDate` |
| Notifications | `timezone`, `notifications`, `fcmTokens`, `updatedDate` |
| FCM token removal | `fcmTokens`, `updatedDate` |

Create rule now requires the full canonical schema including `hasRemoveAds` and `isDetectivePro`.

Added helpers: `intOrZero`, `userGameStateCoreImmutable`, `isValidUserGameStateCreate`, and per-operation `is*Update()` checks.

**File:** `firestore.rules`

## App-side alignment

### Ensure user game state on sign-in
- Added `ensureUserGameState(userId)` to the data source and repository (get existing doc or create with defaults).
- `SaveUserSessionUseCase` now creates the Firestore `userGameStates` doc immediately after saving the local session, so every authenticated user has a complete document before gameplay or notifications run.

**Files:**
- `lib/shared/data/data_source/user_game_state_service.dart`
- `lib/shared/data/data_source/remote/user_game_state/user_game_state_service.dart`
- `lib/shared/domains/repostiories/user_game_state_repository.dart`
- `lib/shared/data/repositories/user_game_state_repository_impl.dart`
- `lib/features/auth/domain/usecases/save_user_session_usecase.dart`
- `lib/di.dart`

### Notification token service
- Removed the `set()` fallback that created incomplete `userGameStates` documents.
- `syncUserNotifications` and `removeToken` now only `update()` when the doc already exists (created at sign-in).

**File:** `lib/features/notifications/data/notification_token_service.dart`
