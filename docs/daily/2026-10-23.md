## CW-005 — Remote Config

### Problem
Crossword tunables (hint penalties, reveals, XP curve, autosave interval, min build) need to change without an app release.

### Solution
Added `firebase_remote_config` (^6.7.0, needed for Remote Config itself). `AppRemoteConfig` (abstract) + `FirebaseAppRemoteConfig` expose typed getters over the five card keys with in-app defaults. `initialize()` sets defaults and activates the last fetched values, then fetches in the background (1 h minimum interval), so startup never waits on the network and works offline; new values apply on the next launch. JSON values are parsed by pure `HintPenalties.parse` / `XpLevelFormula.parse`, which fall back to defaults on bad input. Registered in `di.dart` before other features.

Added nav colours to `MyColors` (`navBarBackground`, `gameBorderSubtle`, `navInactive`) from the tokens. No new packages.

## CW-015 to CW-022 — Crossword callables and scheduled jobs

### Solution
Each function has the same shape: a `*_logic.py` file with the pure parsing and rules, plus its tests; a `do_thing(client, …)` that reads and writes in one transaction (`run_transaction` in `firestore_client.py`); and a thin `@https_fn.on_call` / `@scheduler_fn.on_schedule` handler. Emulator tests (`*_test.py` beside each handler) use the `emulator_db` fixture in `functions/conftest.py`, and are skipped when no emulator is running, so the deploy predeploy hook still passes.
- **adminSaveCategory:** upserts by slug. Counters and creation fields are kept on edit.
- **adminSaveQuestion / adminVerifyQuestion:** the answer is normalized (uppercase; spaces, `-` and `.` removed). Any edit sets the status back to `draft`. Retired questions are locked, and verify refuses a `TODO` source.
- **adminSaveCrosswordPuzzle:** writes the puzzle, solution, `lastPuzzleNumber` and `usedInPuzzles` in one transaction. Each word's answer must match its verified question. Only `draft`/`in_review` puzzles can be re-saved. New fields: `crosswordCategories.lastPuzzleNumber` and `crosswordPuzzles.wordCount`.
- **adminSetPuzzleStatus / adminScheduleDaily:** the transition table, with category counts updated in the same transaction. `scheduled → scheduled` changes `publishAt`. A daily pointer needs a puzzle that is live by 00:00 IST that day.
- **submitCrossword:** idempotent, checks blocked players and the rate limit, and never accepts less time or fewer hints than the saved progress shows. One transaction writes progress, user, leaderboard entry and revision items. Scoring rules are recorded as **DEC-011 (Proposed)**. XP is scaled by correct words, because the literal "xpReward − penalties" would pay full XP for an empty grid. New: input `revealedWordIds`, and `result.revealedWordIds`. If the player has no `users/{uid}` doc, the server creates one, so CW-055 must update an existing doc rather than create it.
- **crosswordDailyRollover:** reads `status == scheduled` (≤ 200 docs), publishes due puzzles (re-checked inside each transaction) and logs an error if today's or tomorrow's daily doc is missing.
- **refreshLeaderboardTop:** reads ≤ 50 entries per run. The first run of an IST week finishes the previous week's board.
- **adminListReports / adminResolveReport:** pages of 20 with `startAfterId`. Resolving records `resolvedBy`, `resolvedAt` and `resolutionNote`, and writes the audit log.
- Cost: no new listeners. `submitCrossword` reads up to 5 docs plus one question per wrong word, and writes 3 docs plus one per wrong word.

**Files:** `functions/crossword/*.py`, `functions/conftest.py`, `functions/firestore_client.py`, `functions/utils/date_id.py`, `docs/firebase/FIREBASE_DESIGN.md`

## CW-026 — Server hint penalties from Remote Config

### Problem
`submitCrossword` used fixed penalties (5/15) that only mirrored the app's Remote Config default.

### Solution
`functions/crossword/remote_config.py` reads the **client** Remote Config template over REST and parses `crossword_hint_penalties` the same way the app does. The card's suggested `firebase_admin.remote_config` server template is a separate namespace, so using it would mean keeping the value in two places. The value is cached for 5 minutes per instance. If a fetch fails, the function keeps the last good value (or 5/15 on a cold start) and never fails a submit. `score_puzzle` and `submit_crossword` now take `penalties` as a parameter. In tests, an autouse fixture in `conftest.py` stops any Remote Config fetch. No new packages: `google-auth` comes with `firebase-admin`. **Not deployed yet.** The live check (change the value on dev, then submit) is still to do.

**Files:** `functions/crossword/{hint_penalties,remote_config}.py` (+ tests), `functions/crossword/submit{,_logic}.py`, `functions/crossword/submit_logic_test.py`, `functions/conftest.py`, `docs/firebase/FIREBASE_DESIGN.md`
