## CW-036 — Bulk upload (questions CSV/JSON, puzzles JSON)

### Problem
The content team would have to type 150+ questions and dozens of puzzles one by one in the panel.

### Solution
"Bulk upload" page. Questions: CSV from a downloadable template (UTF-8 with BOM for Malayalam in Excel), cells pasted from Google Sheets, or `content/questions/*.json`. Puzzles: `content/puzzles/*.json`. Each row is checked like the server does and shown as New / Update / No change / Error before saving; rows with errors are skipped. Re-import matches questions on `subject` + `answer` (identical ones are left alone so checked questions stay checked) and puzzles on `id`, then title in the category (drafts only). `TODO` question ids in puzzle files are linked to checked questions by answer. Status filters on Questions, Puzzles and Reports moved to a shared `FilterChips` widget (wrapping chips instead of a segmented bar that overflowed on narrow screens).

**Package:** `web` — the admin panel opens and saves files in the browser (`package:web` file input and Blob download). It's behind a conditional import (`text_file.dart` → `text_file_web.dart` / `text_file_stub.dart`), so the mobile app and tests never load it.

**Files:** `lib/features/admin/domain/utils/{bulk_import,csv}.dart`, `lib/features/admin/presentation/pages/admin_bulk_upload_page.dart`, `lib/features/admin/presentation/utils/text_file*.dart`, `lib/features/admin/presentation/widgets/filter_chips.dart`, `lib/features/admin/domain/models/admin_puzzle.dart`, `lib/core/routes/admin_router.dart`, admin pages, `pubspec.yaml` (+ tests)

## CW-038: Auto-create puzzle from checked questions

### Problem
Building a crossword by hand means placing every checked question one by one. The admin wants a starting grid made from a category's checked questions that they can review and then save.

### Solution
- `admin/puzzles/domain/utils/auto_puzzle.dart` (pure Dart): `autoPuzzle(questions, AutoPuzzleOptions)` takes checked questions with A–Z answers that fit the grid, keeps one question per answer, applies the difficulty filter, and puts unused questions first. Each attempt puts one long word across the middle, then keeps adding the word whose best `PuzzleDraft.suggestions` spot crosses the most letters (ties go to the spot nearer the centre). It makes 40 seeded attempts and keeps the one with the most words, then the most crossings, then the most filled squares; an attempt is dropped if `problems` isn't empty after `trimmed()`. The same seed always gives the same grid.
- `placementFor()` (in `puzzle_draft.dart`) now does the question → placement mapping, and the builder's `_place()` calls it. `suggestions()` now only tries start squares that line up a matching letter. It returns the same spots and is much faster (about 20 ms per generated grid).
- Builder: `/puzzles/new?category=<id>&auto=1[&size&words&difficulty]` fills the grid without saving it (`_dirty`, so leaving asks first). The title becomes "<Category> mix", difficulty is the most common one among the questions used, and minutes is set to max(3, words). An `AutoPuzzleCard` above the grid has "Try another" (next seed; Undo goes back) and "Options". When there aren't enough questions, the card explains why and links to `/questions?subject=`. The auto-fill code is in the `puzzle_builder_auto.dart` part file.
- Categories: a ✨ row action. Questions: an "Auto-create puzzle" button that opens a dialog (category, size, words, difficulty, and the checked count when all of them are loaded). It goes to the builder by `AdminRoutes.autoPuzzle` only, without importing the puzzles module. The shared `AutoPuzzleFields` widget lives in `admin/shared/presentation/widgets/`.
- `test/fixtures/admin/auto_puzzle.puzzle.json` is a generated grid. The Dart test (exact output) and the Python `validate_puzzle` test both check it.
- No packages, functions, rules, indexes or schema changed, so nothing to deploy. Nothing is saved, verified or published automatically.

Checks: analyze shows only the 6 accepted issues, structure 0 problems, 240 Flutter tests, ruff + 243 pytest green.
